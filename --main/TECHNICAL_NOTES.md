# 技术说明与维护备注

本文补充 `README.md` 中不适合展开的实现细节，内容依据当前代码整理，未修改项目逻辑。

## 核心数据流

1. `TLEManager` 读取非空行，识别两行式或三行式 TLE。
2. 两行式数据使用 NORAD 目录号作为索引，并生成 `NORAD-<id>` 显示名称；三行式数据同时按名称和 NORAD ID 建立索引。
3. `OrbitPropagator` 为每颗选中卫星创建 Skyfield `EarthSatellite`，一次性外推整个时间窗口。
4. `SimulationController` 按共同时间索引提取卫星快照。
5. `TopologyBuilder` 把经纬高近似转换为球形地球下的 ECEF 直角坐标，并构建 NetworkX 无向图。
6. `RoutingEngine` 在单帧图上寻路，累加边的 `distance_km`，再按真空光速计算单向传播时延。
7. Web 模式把结果序列化为 JSON 发送给 Cesium；离线模式把每帧结果追加到 DataFrame 并导出 CSV。

## 拓扑构建规则

### 星间链路（ISL）

- 用 `scipy.spatial.cKDTree.query_pairs()` 搜索最大通信距离内的候选卫星对，避免直接构造完整的 N×N 距离矩阵。
- 排除空间坐标完全重合的零距离候选边。
- 对候选边执行球形地球遮挡判定。
- 可见候选边按距离从短到长处理；任一端卫星达到 `max_neighbors_per_satellite` 后，不再接受更多 ISL。
- 边属性包含 `weight`、`distance_km` 和 `type="ISL"`。

该度数限制使用贪心策略，因此结果受候选边距离排序影响，并不保证得到全局最优的受限度数拓扑。

### 星地链路（SGL）

- 地面站被加入图中，节点类型为 `GS`。
- 计算地面站天顶方向与站星视线的夹角，得到仰角。
- 仰角大于或等于 `min_elevation_deg` 的卫星均与地面站建立链路。
- SGL 不受卫星 ISL 邻居数上限约束，也没有单独设置最大距离。
- 边属性包含 `weight`、`distance_km` 和 `type="SGL"`。

当前固定地面站为：

| 节点 | 纬度 | 经度 | 高度 |
| --- | ---: | ---: | ---: |
| `GS-Beijing` | 39.9042 | 116.4074 | 0 km |
| `GS-Singapore` | 1.3521 | 103.8198 | 0 km |

## 路由结果格式

`RoutingEngine` 的两种策略返回统一字典：

```python
{
    "success": True,
    "source": "GS-Beijing",
    "target": "GS-Singapore",
    "path": ["GS-Beijing", "NORAD-...", "GS-Singapore"],
    "hops": 2,
    "total_distance_km": 1234.5,
    "propagation_delay_ms": 4.1178,
    "error_msg": ""
}
```

节点不存在或路径不可达时，`success` 为 `False`，路径和各数值指标保持空值/零值，并通过 `error_msg` 给出原因。

## WebSocket 快照格式

`/ws` 每次发送的结构如下：

```json
{
  "timestamp": "2026-07-21T12:00:00+00:00",
  "nodes": {
    "NORAD-00005": {
      "lat": 10.1234,
      "lon": 20.5678,
      "alt": 500.0,
      "type": "SAT"
    },
    "GS-Beijing": {
      "lat": 39.9042,
      "lon": 116.4074,
      "alt": 0.0,
      "type": "GS"
    }
  },
  "topology_edges": [
    ["GS-Beijing", "NORAD-00005"]
  ],
  "active_route": {
    "success": true,
    "path": ["GS-Beijing", "NORAD-00005"],
    "delay_ms": 3.25,
    "hops": 1
  }
}
```

节点的卫星高度来自轨道外推，单位为 km；前端渲染时乘以 1000 转为 Cesium 所需的米。

## Web 与离线模式差异

| 项目 | Web 模式（`main.py`） | 离线模式（`simulation_controller.py`） |
| --- | --- | --- |
| 仿真起点 | 启动 WebSocket 时的 UTC 时间 + 1 天 | 进程启动时的 UTC 时间 + 1 天 |
| 默认时长 | 60 分钟 | 60 分钟 |
| 步长 | 1 秒 | 1 秒 |
| 最大 ISL 距离 | 5000 km | 6000 km |
| 最大 ISL 邻居数 | 6 | 6 |
| 最小 SGL 仰角 | 15° | 15° |
| 卫星数上限 | 50 | 50 |
| 电量模型 | 未调用 | 每个快照调用 |
| 输出 | WebSocket/Cesium | CSV 和终端 QoS 报告 |
| 执行节奏 | 每帧后等待约 0.1 秒 | 尽快完成全部帧 |

虽然 `setup_environment()` 的终端文案写着“并行推算”，当前实现实际是逐颗卫星依次调用传播器。

## 电量模型

电量模型只在离线 `run_simulation()` 中生效：

- 所有卫星初始电量为 100%。
- 用简化的太阳方向和圆柱形地影模型判断卫星是否处于地影。
- 地影中按 `1.0% × step_seconds` 放电。
- 光照中按 `0.5% × step_seconds` 充电。
- 电量限制在 0%～100%；达到 0% 的卫星从当前拓扑快照移除。

这些速率是演示参数，不对应具体卫星平台的真实功耗、载荷或太阳翼能力。

## 模型假设与已知限制

### 物理与网络模型

- 轨道传播使用 Skyfield/SGP4 和 WGS84 输出；拓扑几何计算则把地球近似为半径 6371 km 的球体。
- ISL 只考虑最大距离、球形地球遮挡和邻居数上限，没有考虑天线指向、链路预算、频段、带宽、姿态、捕获时间或终端数量。
- SGL 只使用仰角阈值，没有大气、地形、天气、干扰、波束覆盖或容量限制。
- 时延仅为 `路径总距离 / 299792.458 km/s`，属于理想单向传播时延。
- 路由基于彼此独立的离散快照，没有控制面收敛时间、链路预测、滞回或切换代价。
- `min_hops` 只优化跳数；在跳数相同时，具体路径由 NetworkX 和图中边的插入顺序决定。
- QoS 报告中的“路由平均寿命”采用 `总时长 / (切换次数 + 1)` 的简化估算。

### 数据与配置

- 两个主入口使用机器相关的绝对 TLE 路径，不具备开箱即用的跨机器可移植性。
- 仿真参数、地面站、Cesium Token、WebSocket 地址等都直接写在源码中。
- 三行式 TLE 会同时产生名称和 NORAD ID 两个索引；批量选择时可能把同一颗物理卫星当成两个标识选中。拓扑构建器会过滤二者之间的零距离边，但不会自动去重卫星实体。
- TLE 文件没有随附数据源、抓取时间、更新方法和许可说明。
- Skyfield 首次初始化时间尺度时可能需要下载或缓存天文数据；离线环境应提前准备缓存。

### Web 服务

- `sim_state` 是进程级全局字典。多个浏览器会共享源节点、目的节点和策略，不能视为相互隔离的会话。
- 每个 WebSocket 连接都会单独创建控制器并预计算轨迹；客户端增多时，CPU 和内存开销会近似按连接数增长。
- WebSocket 地址固定为 `ws://localhost:8000/ws`，不适配非本机访问、非 8000 端口或 HTTPS 部署。
- 页面依赖外部 Cesium CDN、World Terrain 和代码中公开的 Cesium Ion Token。公开部署前应单独管理 Token、限制权限并检查许可/配额。
- API 更新节点时没有验证节点是否存在；无效节点会在后续快照中表现为路由失败。
- Web 模式未使用离线模式中的电量过滤逻辑，因此两个模式在长时间运行时可能得到不同拓扑。
